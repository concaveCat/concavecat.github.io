    《数据结构与算法》复习04：栈与队列

    一、栈的描述

    栈是一种受限的先进后出序列，只能在栈顶（top）插入和删除，栈底无法访问，是盲端。

    可以直接基于向量或列表派生：

    template <typename T>
struct stack: public vector<T> {
	void push( const T& e );
	T pop() { return remove(_size-1); }
	T& top() { return _elem[_size-1]; }
}

    二、调用栈

    2.1 从调用树到调用栈

    • 函数调用树（Call Tree）：从全局视角将复杂的函数嵌套/递归关系抽象为树状结构。每一个节点代表一次调用，分支代表其派生的子调用。

    • 调用栈（Call Stack）：底层运行期用来管理控制流的内存区域。采用后进先出（LIFO）原则，确保嵌套函数能正确挂起和原路返回。栈内的元素叫作栈帧（Stack frame）。

    • 栈帧（Stack Frame）：包含返回地址和局部变量。调用时压栈，return 时出栈。

    • 递归算法需要的空间主要取决于递归深度，而不是递归实例总数，因为调用栈会被弹出。

    2.2 消除递归

    为了减少递归函数的空间复杂度，一般有两种方式：

    1. 显式维护调用栈：可以将递归放在堆内存中进行，且递归存储数据可以变少；
    2. 将递归算法改写为迭代算法，彻底消除递归。

    2.3 尾递归

    最简单的尾递归如下：

    function ( ... ) {
	...
	function ( ... );
	return ...;
}

    即唯一的一句递归调用恰好发生在函数末尾，return 之前。在实际执行这段代码的过程中，（不考虑编译器优化）nnn 个栈帧会被压入栈空间，一旦抵达递归基，就会出现连续的 nnn 个 pop 操作，调用栈瞬间清空。

    现代编译器会对尾递归执行尾递归优化，直接转换成递推，空间复杂度于是有了渐进改进。

    while ( ... ) {
	function1( ... );
}

    2.4 头递归

    头递归的一个例子是短除法实现进制转换：

    void convert ( int n, int base ) {
	const char digit[] = "0123456789ABCDEF";
	if ( n < 1 ) return;
	convert( n / base, base ); // 先输出高位
	output( digit[n % base] ); // 再输出低位
}

    它被称为头递归，是因为显然，递归调用语句在函数的主体之前。这种递归同样可以被类似地化简为递推操作。

    下面，我们手动模拟调用栈来实现这种操作；记住手动模拟调用栈的好处：（1，分配在堆内；2，常系数更小）

    void convert ( int n, int base ) {
	const char digit[] = "0123456789ABCDEF";
	stack<char> S;
	while ( 0 < n ) {
		S.push( digit[n % base] ); // 逆序输入
		n /= base;
	}
	while ( !S.empty() ) 
		output( S.pop() ); // 正序输出
}

    double eval( char* S, char* RPN ) {
	stack<double> opnd; 
	stack<char> optr;
	for ( optr.push('\0'); !optr.empty(); ) {
		if ( isdigit( *S ) ) {

			append( RPN, opnd.top() );
		}
		else

}

    五、逆波兰表达式 RPN

    逆波兰表达式是一种不使用括号即可表示带优先级的运算关系。RPN 亦称作后缀式（postfix）。RPN 对计算机很友好，因为只需要出栈和入栈就可以完成计算操作了。

    double RPN( char* S ) {
	stack<double> opnd;
	for ( char* i = strtok( S, " " ); item(); item = strtok( nullptr, " " ) )
		if ( 1 < strlen( item ) || isdigit( item[0] ) )
			opnd.push( atof( item ) );
		else
			opnd.push( calc( opnd, item[0] ) );
	return opnd.pop();
}

    六、栈混洗 Stack Permutation

    6.1 概念解释

    栈混洗，就是将栈 A 的数据随机地洗到输出序列 B 中。这其中要借助一个栈 S，栈 S 负责随机执行下面两个操作之一：

    • 从栈 A 吸入一个元素；
    • 给输出序列 B 投喂一个元素。

    在栈 A 和 S 空之后，栈混洗完成。

    6.2 方法数：catalan(n)\text{catalan}(n)catalan(n)

    nnn 个元素的栈混洗有多少种类？由于 S 不能为空，显然种类数是

    C(n)=:catalan(n)=1n+1C2nn.C(n) =: \text{catalan}(n)= \frac{1}{n+1} C_{2n}^n.C(n)=:catalan(n)=n+11​C2nn​.

    递推式也需要记住：

    Cn=∑k=1nCk−1Cn−kC_n = \sum_{k=1}^{n} C_{k-1} C_{n-k}Cn​=k=1∑n​Ck−1​Cn−k​

    设入栈序列为 1,…,n1, \dots, n1,…,n。若元素 kkk 是最后出栈 S 的，则在 kkk 入栈前，比它小的 k−1k-1k−1 个元素已完成了一次完整的栈混洗（共 Ck−1C_{k-1}Ck−1​ 种）；在 kkk 出栈前，比它大的 n−kn-kn−k 个元素也已在中转栈上方完成了混洗（共 Cn−kC_{n-k}Cn−k​ 种）。对这 nnn 种情况相加即得答案。

    6.3 禁形检测

    对于三个元素 1, 2, 31,\,2,\,31,2,3，如果我们想让 333 在输出序列的最前面，就必须按照 1−2−31-2-31−2−3 的顺序将他们压入栈，于是输出序列不可能生成类似 3−1−23-1-23−1−2 的结构。3−1−23-1-23−1−2 即禁形。

    一个序列是栈混洗， 当且仅当其中不含任何禁形。

    直接模拟混洗操作就可以检测给定序列 B 中的禁形。对于一个升序序列 A（1,2,3,…,n），不断将其中元素压入栈 S：

    • 若 S.top == B[i]，那么正好匹配输入序列，s.pop(), i++。
    • 若 S.top != B[i]，那么说明还没有压完，继续压：S.push。
    • 若 A 的元素已经拿完了（n < A） / 待匹配的元素被堵住了（B[r] < A），那么匹配算法直接失败，return。

    将A、 B操作对应于左、右括号： n个元素的栈混洗，一一对应于n对括号的匹配表达式。

    八、双栈当队

    我们用两个栈来模拟一个队列；栈 A 负责读数据，将读到的数据倒给栈 B，然后栈 B 负责写数据。

    在某些专为特定任务设计的硬件（如特定型号的 FPGA、流水线处理器、或某些微控制器/低级嵌入式系统）中，硬件层面可能只原生提供了栈结构（通过堆栈指针 Stack Pointer 实现），而没有提供链表或循环数组等标准的队列硬件支持。此时，用两个现成的栈去模拟队列是最直接、开销最小的方案。

    在并发编程中，双栈结构天然地将写操作（入队）和读操作（出队）在绝大多数情况下解耦开来：

    线程 A 可以持续向 In-Stack 写入数据。

    线程 B 可以持续从 Out-Stack 读取数据。

    由于两个线程在不同的大多数时间操作的是不同的内存区域（不同的栈顶），这可以极大地减少锁的粒度（甚至可以使用无锁的 CAS 操作分别限制两个栈顶），从而提高多线程环境下的吞吐量。只有在 Out-Stack 耗尽、需要从 In-Stack 迁移数据时，才需要进行全局同步。

    双栈当队的时间复杂度仍然是 O(n)O(n)O(n)，因为根据记账法，每个元素都需要 444 次移动，总数是 4n4n4n。

    九、记账法

    记账法（Accounting Method）是算法分析中用来计算摊还复杂度（Amortized Complexity）的一种直观方法。它的核心思想非常生活化：“存钱养老，平摊开销”。在很多数据结构中，大部分时候的操作都非常快（比如 O(1)\mathcal{O}(1)O(1)），但偶尔会遇到一次极慢的操作（比如 O(n)\mathcal{O}(n)O(n) 的扩容或去重移动）。为了不让偶尔的暴击吓到我们，我们用记账法来重新分配成本。

    • 设定统一的“摊还代价”（Amortized Cost）：

      对于那些原本很快的操作，我们故意向它多收一些虚拟金币。

    • 存入银行（Credit）：

      多收的金币不会消失，而是作为存款存进这个数据结构（或某个特定元素）的账户里。

    • 取出贴补：

      当遇到那个偶尔发生、非常昂贵的巨额操作时，算法自己掏不出那么多钱，就从银行里把之前的存款全部取出来，用来支付这次大额开销。

    • 大原则：不能透支！

      在算法运行的任何一个时刻，你的总存款都必须 ≥0\ge 0≥0。只要能证明这一点，那么你定的这个“摊还代价”就是合法的，它就是该算法宏观上的平均时间复杂度。

    9.1 双栈当队的记账分析

    1. 给队列中的每个元素派发 4 credits。（每个元素进栈需要 1，移动需要 2，出栈需要 1）
    2. 每次读需要 1 credit，写需要 1 credit，由对应的元素支付。
    3. 移动需要 2n credits，由全体元素支付。

    9.2 vector::dedup 的记账分析

    我们复习 dedup 的处理逻辑：从前向右扫描，对扫描到的每一个元素，寻找它左侧是否有和他相同的元素，如果有，那么删去它左侧的那个元素。

    接下来我们给位置序号为 kkk 的元素派发 n−kn-kn−k credits。比如，第一项元素的 k=0k=0k=0，所以有 nnn 个 credit。

    • 对于每一次比较，如果某元素被后面的元素比到了，那么它自己扣一个 credit，变成 n−k−1n-k-1n−k−1 credit。

    • 对于每一次比较，如果元素 rrr 被选定删除了，那么：

      设选定删除它的人是 kkk。

      被删除之前，这个元素被 [r+1,k)∩N[r+1,k) \cap \mathbb{N}[r+1,k)∩N 这 k−rk-rk−r 个元素比较过，剩余的 credit 应该是 n−r−(k−r)=n−kn-r-(k-r)=n-kn−r−(k−r)=n−k。我们考察删除动作：

      删除的动作，即将 [r+1,n]∩N[r+1, n] \cap \mathbb{N}[r+1,n]∩N 这 n−rn-rn−r 个元素前移一位，但是元素 rrr 只有 n−kn-kn−k 个 credit。我们清空元素 rrr 的 n−kn-kn−k 个 credit，这些 credit 足以用来支付 [k+1,n]∩N[k+1,n]\cap \mathbb{N}[k+1,n]∩N 这 n−kn-kn−k 个元素前移一位的开销。对于 [r+1,k][r+1,k][r+1,k] 这 k−rk-rk−r 个元素，它们前移的开销则由自己支付。（注意到这样支付的 credit 和被 kkk 正常比较时支付的 credit 是一样的！）

    因此，总 credit 数可以来到 n(n+1)2\frac{n(n+1)}{2}2n(n+1)​。

    十、聚合法

    聚合法的核心思想是：不要孤立地去看单次操作的最坏情况，而是去考察一个由 nnn 次操作组成的任意操作序列的总代价。 如果一个包含 nnn 次操作的序列在最坏情况下的总时间复杂度是 T(n)T(n)T(n)，那么平均下来，每步操作的摊销代价就是：

    \frac{T(n)}{n}

    十一、势能法

    把数据结构看作一个物理系统。每当执行一个操作，系统的状态就会发生变化，从而改变系统的“势能” Φ\PhiΦ：

    • 省钱存入（势能增加）： 如果某个操作的实际代价很低，我们可以人为地多支付一点代价值，把多余的价值转化为“势能”存储在数据结构中。

    • 花钱贴补（势能减少）： 当遇到某个实际代价极高的操作时（比如需要清空或转移整个结构），我们可以释放存储的“势能”来贴补这个高昂的实际代价。

    通过这种方式，原本高低不平的实际代价就被“抹平”成了稳定、低廉的均摊代价。

    对于第 kkk 次操作：

    A_k = T_k + \Phi_k - \Phi_{k-1}

    • AkA_kAk​：第 kkk 次操作的均摊代价（Amortized Cost）——这是我们想求的稳定值。

    • TkT_kTk​：第 kkk 次操作的实际代价（Actual Cost）——这取决于具体的算法实现。

    • Φk\Phi_kΦk​：操作完成后的系统势能。

    • ΔΦ=Φk−Φk−1\Delta\Phi = \Phi_k - \Phi_{k-1}ΔΦ=Φk​−Φk−1​：系统势能的增量。

    相比于记账法，势能法不需要管钱存在谁那，只需要盯着数据结构的宏观状态。例如：“我的势能函数就是当前栈 RRR 的长度减去栈 FFF 的长度。” 它把所有元素的贡献直接浓缩成了一个整体指标。

    这里的势能定义直观，即栈 Q 的元素和栈 P 的元素个数相减。

    Φk=∣Qk∣−∣Pk∣\Phi_{k}=|Q_{k}|-|P_{k}|Φk​=∣Qk​∣−∣Pk​∣

    那么每一步的均摊代价就是

    Ak=Tk+Φk−Φk−1=2.A_{k}=T_{k}+\Phi_{k}-\Phi_{k-1}=2.Ak​=Tk​+Φk​−Φk−1​=2.

    在转移时，实际代价 Tk=2mT_{k}=2mTk​=2m，但是势能 −2m-2m−2m，因此不影响均摊代价。

    2n=∑k=1nTk+Φn−Φ0=∑k=1nTk+Φn2n = \sum_{k=1}^{n}T_{k}+\Phi_{n}-\Phi_{0}=\sum_{k=1}^n T_{k}+\Phi_{n}2n=k=1∑n​Tk​+Φn​−Φ0​=k=1∑n​Tk​+Φn​

    十二、直方图内最大矩形

    给定一组非负整数表示直方图各柱子的高度，各柱子紧邻且宽度均为 1。求在该直方图中，由若干相邻柱子所能勾勒出的最大矩形面积。

    12.1 暴力法

    扫描每一对柱子的组合，计算以两根柱子为左右边界的矩形的最高高度，总共需要 O(n2)O(n^{2})O(n2) 时间。

    12.2 单调栈

    通过维护一个栈，只需要 O(n)O(n)O(n) 时间扫描一遍即可完成任务。对遍历到的每个柱子，我们考虑被它撑起来的最大矩形面积（ 柱子的高度 hhh 乘以最大宽度 d=r−ld=r-ld=r−l，rrr 是右边界，即会卡住这个柱子的位置，lll 是左边界 ）。具体规则如下：

      计算得出的面积是 5×(4−3)=5.5 \times (4-3)=5.5×(4−3)=5.

    十三、最大栈和最大队列

    13.1 最大栈

    最大栈的意思是：对一个栈 S，我们将 S 从底端到顶端遍历，记录一个局部最大值序列，得到的单调栈就是最大栈。最大栈的目的是：在不破坏标准栈“后进先出”特性的前提下，让获取当前栈内最大值（getMax()）的操作达到 O(1)O(1)O(1) 的时间复杂度。

    一般来说，最大栈在原栈创建的时候就同步创建了；否则，创建最大栈需要把原来栈内的所有内容全都倒出来再重新创建两个栈，比较耗时。

    对一个 nnn 个元素的栈，其最大栈有两种创建方式：

    • 最大栈内也有 nnn 个元素，每个元素是其局部最大值。可以想到会有不少重复元素。
    • 只有在最大栈需要更新时，才记录新元素及其对应位置。需要记录位置和值两个变量。

    13.2 最大队列

    最大队列的意思是：对一个队列 Q，将 Q 从队尾到队首遍历，记录一个局部最大值序列，得到的单调队列就是最大队列。

    创建方式和最大栈相似。

    13.3 均摊成本

    O(1)O(1)O(1).
