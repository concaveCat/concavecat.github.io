    《数据结构与算法》复习 08：高级搜索树

    一、伸展树

    刚被访问过的节点，极有可能很快地再次被访问；下一将要访问的节点，极有可能就在刚被访问过的节点附近。

    1.1 早期的逐层伸展策略

    为了不破坏 BST 的有序性（左小右大），移动节点只能借助逐层旋转。如果树退化为很深的单支树（类似“死蛇挂树”，高度为 nnn），那么一个周期中累计消耗时间高达 Ω(n2)\Omega(n^2)Ω(n2)，折合到每次操作的均摊时间复杂度为 Ω(n)\Omega(n)Ω(n)。

    1.2 双层伸展策略

    核心逻辑：先旋祖父，再旋父亲。

    在普通的逐层单旋中，单支树在操作后只是“方向调转”（从左斜变成右斜），树高几乎没变。在双层伸展中，因为每次 LL/RR 都是先撬动祖父，导致被访问路径上的所有祖先节点，其深度全部平均减少了约一半。

    1.3 势能法均摊分析

    时间复杂度说的是单次访问 / 维护操作的均摊时间复杂度。

    template <typename T> 
BNP<T> Splay<T>::splay( BNP<T> v ) { // 节点v伸展至根
    while ( BNP<T> p = v->parent ) // 自下而上
        if ( BNP<T> g = p->parent ) { // 若有祖父，则做双层伸展
            if ( BNP<T> gg = v->parent = g->parent ) // 伸展之后
                g == gg->lc ? gg->attachLc( v ) : gg->attachRc( v ); // v应该原曾祖父为父
            switch ( ((p == g->rc) << 1) | (v == p->rc) ) { // 视p、v之拐向，分四种情况做伸展
                case 0b00 : g->attachLc( p->rc );  p->attachLc( v->rc );
                            p->attachRc( g );     v->attachRc( p );     break; // LL
                case 0b01 : p->attachRc( v->lc );  g->attachLc( v->rc );
                            v->attachRc( g );     v->attachLc( p );     break; // LR
                case 0b10 : p->attachLc( v->rc );  g->attachRc( v->lc );
                            v->attachLc( g );     v->attachRc( p );     break; // RL
                default   : g->attachRc( p->lc );  p->attachRc( v->lc );
                            p->attachLc( g );     v->attachLc( p );     break; // 0b11 ~ RR
            }
            g->updateHeight(); p->updateHeight();
        } else { // 若父亲即根（只可能在最后一步出现一次），则做单层伸展
            if ( v == p->lc ) { p->attachLc( v->rc ); v->attachRc( p ); } // L情况
            else              { p->attachRc( v->lc ); v->attachLc( p ); } // R情况
            p->updateHeight(); v->parent = nullptr; break;
        } // else
    (_root = v)->updateHeight(); print(this); return v; // v终成树根
} // splay
    template <typename T> 
BNP<T> Splay<T>::insert( const T& e ) { // 将关键码e插入伸展树中
    if ( !_root ) { _size = 1; return _root = new BinNode<T>( e ); } // 原树为空
    search( e ); if ( e == _root->data ) return _root; // 查找成功（否则，_p已伸展至根）
    if ( _p->data < e ) // 在右侧嫁接（rc或为空，lc == _p必非空）
        { _root = new BinNode<T>( e, nullptr, _p, _p->rc ); _p->rc = nullptr; }
    else // e < _p->data: 在左侧嫁接（lc或为空，rc == _p必非空）
        { _root = new BinNode<T>( e, nullptr, _p->lc, _p ); _p->lc = nullptr; }
    _p->updateHeightAbove(); _size++; return _root;
} // insert
    template <typename T> 
bool Splay<T>::remove( const T& e ) {
    search(e); // 首先做一次查找
    if ( !_root || e != _root->data ) return false; // 若成功，则命中节点必已伸展至根
    BNP<T> L = _root->lc, R = _root->rc; delete _root; _size--; // 记下子树L、R后，释放之
    if ( !R ) {
        if ( _root = L ) // 若R空，则
            _root->parent = nullptr; // L即是余树
    } else { // 否则，在R中再次查找e：尽管这次查找必然失败...
        (_root = R)->parent = nullptr; search( e ); // ...但R的最小节点会伸展为根，且无左孩子
        _root->attachLc( L ); _root->updateHeight(); // 故只需令L作为其左子树，便成一棵完整的树
    } // else
    return true;
} // remove

    二、B-树

    2.1 就地循环左移

    将一个长度为 n 的数组 A[0, n) 向左循环移动 m 个单元（例如：[0,1,2,3,4,5,6,...] 移动后变成 [6,7,...0,1,2,3,4,5]），仅允许使用 O(1)O(1)O(1) 的辅助空间。

    2.1.1 经典轮换法

    通过最大公约数 d=gcd(n,m)d = \text{gcd}(n, m)d=gcd(n,m) 将数组分成 d 个独立的循环链。每个链内部的元素以 m 为步长依次向前跳跃赋值。理论上这已经达到了移动次数的最优解，但是因为它是以 m 为步长“跳跃式”访问内存的，缓存命中率极低。

    2.1.2 并行轮换法

    先开辟一个大小为 d 的辅助空间（严格来说这违背了 O(1)O(1)O(1) 的就地要求），把所有轮换链的第一个元素都备份下来。然后让所有轮换链“并行”向前移动。在主要的两重循环中，将一部分访问变成了 1 步长，一部分保留为 m 步长。当 ddd 较大时性能有所改善。

    2.1.3 三次翻转法

    先翻转前 m 个元素，再翻转后 n-m 个元素，最后整体翻转整个数组，来实现左移的目标。总共需要 3n3n3n 次移动，在物理移动次数上明显多于算法一，但是它的实际运行速度反而最快；这是因为它将缓存的预取和高速命中发挥到了极致。

    2.1.4 缓存友好型代码

    当指针连续移动（lo++ 或 --hi）时，计算机一次性加载到 Cache 里的一个内存块可以被连续使用多次（多次 Hit，极少 Miss）。当指针按 j += m 大步长跳跃时，每次跳跃都会跳出当前已加载的缓存块，导致每一次访问都需要重新去慢速的主存（RAM）中读取，从而产生密集的 Cache Miss。

    2.2 B-树的结构

    二叉树每往下走一层，就可能需要进行一次磁盘 I/O。因此，可以把多层节点合并成一个大节点；把每 ggg 层合并一次，树的高度就会降为原来的 1/g1/g1/g。一个合并后的节点正好可以填满一个磁盘缓存页，这样一次 I/O 就能读入一整组数据，大大减少了访问外存的次数。

    表示方式如下：

    一个节点内有 kkk 个关键码，它们按升序排列：K1<K2<⋯<KkK_1 < K_2 < \dots < K_kK1​<K2​<⋯<Kk​；这些关键码会把整个实数轴切分成 k+1k+1k+1 个开区间；每一个区间，正好对应一个指向子树的指针。

    B-树存在半载下限：（根节点无视此规则）

    树的阶数 m (上限)孩子分支数下限 a=⌈m/2⌉每个节点允许的关键码（数据）数量区间对应的经典树类型
    m=3m = 3m=3⌈3/2⌉=2\lceil 3/2 \rceil = \mathbf{2}⌈3/2⌉=2[1,2][1, 2][1,2] 个关键码2-3 树
    m=4m = 4m=4⌈4/2⌉=2\lceil 4/2 \rceil = \mathbf{2}⌈4/2⌉=2[1,3][1, 3][1,3] 个关键码2-3-4 树
    m=5m = 5m=5⌈5/2⌉=3\lceil 5/2 \rceil = \mathbf{3}⌈5/2⌉=3[2,4][2, 4][2,4] 个关键码(3,5)-树
    m=256m = 256m=256⌈256/2⌉=128\lceil 256/2 \rceil = \mathbf{128}⌈256/2⌉=128[127,255][127, 255][127,255] 个关键码现代数据库常用配置
    template <typename T> struct BTNode;
template <typename T> using BTNP = BTNode<T>*; // B-Tree Node Position

template <typename T> struct BTNode {
    BTNP<T> parent; Rank height; // Height(nullptr) = 0, 其余递推
    Vector<T> key; Vector<BTNP<T>> way; // 关键码向量、孩子向量 (后者长度总是多一个单位)
    
    BTNode( Rank b, Rank h = 1, BTNP<T> c = nullptr ) // b阶
        : key(b), way(b+1), parent(nullptr), height(h) // 初始时，无关键码
    { if (c) { way.insert(c); c->parent = this; } } // 但可能会有个分支
}; // BTNode
    template <typename T> struct BTree {
    const Rank _a, _b; Rank _N; BTNP<T> _root; // 分支数的上、下限；关键码总数；根节点
    BTree( Rank m = 3 ) : _a( (m+1)/2 ), _b( m ), _N( 0 ), _root( new BTNode<T>( m ) )
        { _root->way.insert( nullptr ); } // 初始空树：根节点无关键码，但有一棵空分支
    ~BTree() { clean( _root ); } // 释放所有节点
    BTNP<T> search( const T& ); BTNP<T> _x; Rank _k; // 无论成功与否，查找总是终止于_x->key[_k]
    bool insert( const T& ); void solveOverflow(); // 插入及上溢修复
    bool remove( const T& ); void solveUnderflow(); // 删除及下溢修复
}; // BTree
    template <typename T> void clean( BTNP<T> x ) {
	if ( !x ) return;
    for ( Rank k = 0; k < x->way.size(); k++ )
       clean( x->way[k] );
    delete x;
} //clean

    2.3 B-树的查找

    在每个节点内顺序查找，如果找到则返回查找成功，否则找到孩子节点将其读入内存。

    template <typename T> BTNP<T> BTree<T>::search( const T& e ) {
    for ( _x = _root; ; _x = _x->way[_k+1] ) { //自根而下，逐层深入（I/O）
       _k = _x->key.search( e ); //简便起见用了二分查找，但此时改用顺序查找亦无妨
       if ( (-1 != _k) && (e == _x->key[_k]) ) return _x; //命中于节点_x->key[_k]
       if ( !_x->way[_k+1] ) return nullptr; //失败于叶节点_x
    }
} //search

    2.4 B-树的插入和上溢分裂

    新的关键码永远会存入叶子节点。overflow 发生在叶子节点满员的情况下，此时叶子节点需要将中间的元素上交，并分裂成两个新叶子。如果上交后父亲节点溢出，此时需要继续上交分裂。根节点类似，若根节点溢出，则需要上交中位数节点作为新的根节点（这是树长高的唯一途径）。

    Template <typename T> bool BTree<T>::insert( const T& e ) {
    if ( search( e ) ) return false; //确认e尚不存在（查找终止于叶节点_x->key[_k]）
    _x->key.insert( _k+1, e );  _x->way.insert( nullptr ); //插入关键码，并增加一个外部节点
    _N++; solveOverflow(); return true; //如上溢，则修复之
} //insert

template <typename T> struct LinkParent {
    BTNP<T> parent; LinkParent(BTNP<T> p) : parent(p) {}
    void operator() (BTNP<T> x) { if (x) x->parent = parent; }
}; // /LinkParent

template <typename T> void BTree<T>::solveOverflow() { // 修复上溢
    while (_b < _x->way.size()) { // _x上溢：|way|-1 == b == |key|
        Rank s = _b - _a + 1; // _x将以中位数为界，将后缀转移至
        BTNP<T> u = new BTNode<T>(_b, _x->height); // 分裂出来的新节点u
        u->key.insert(0, _x->key, s, _b); _x->key.remove(s, _b); // 关键码
        u->way.insert(0, _x->way, s, _b + 1); _x->way.remove(s, _b + 1); // 孩子
        u->way.traverse(LinkParent<T>(u)); // u的孩子们统一指向u
        BTNP<T> p = _x->parent; // _x的父亲p：若为空，则创建之，且
        if (!p) _root = p = new BTNode<T>(_b, 1 + _x->height, _x); // 全树长高一层
        _k = p->way.find(_x); // 确定_x在p中的秩
        p->key.insert(_k, _x->key.remove(s - 1)); // 轴点上升
        p->way.insert(_k + 1, u); u->parent = p; // u与p互联
        _x = p; // 上升一层，继续修复——至多可能上溯O(logn)层、分裂O(logn)次
    } // /while
} // /solveOverflow

    2.5 B-树的删除与下溢

    如果叶子节点已经处于半满状态，继续删除后就会因为节点太小而违约；underflow 发生。他有两种情况：

    • 兄弟节点还很大，从兄弟节点借一个元素——旋转（将兄弟节点的相邻元素顶到父亲上，将父亲原来的元素补给太小的节点）；
    • 兄弟节点也是半满，和兄弟节点合并（父亲节点下移）。
    template <typename T> bool BTree<T>::remove( const T& e ) {
    if ( !search( e ) ) return false; // 确认e的确存在 (于_x->key[_k])
    if ( _x->way[0] ) { // 即便x不是叶子，亦可经过如下的腾挪，使之“成为”叶子
        BTNP<T> s = _x->way[_k+1]; // 在右子树中一路向左，末端叶节点s中的首个关键码
        while ( s->way[0] ) s = s->way[0]; // 就是e的后继
        _x->key[_k] = s->key[0]; _x = s; _k = 0; // 令e与之“交换”
    } // 至此，x必是叶节点，且e“是”其中的第k个关键码
    _x->key.remove( _k ); _x->way.remove(); _N--; // 删除e以及其下的一个外部节点
    solveUnderflow(); return true; // 如下溢，则修复之
} // /remove

template <typename T> void BTree<T>::solveUnderflow() { // 修复下溢
   while (_a > _x->way.size()) { // _x下溢：|way| = a-1 = |key|+1
      BTNP<T> p = _x->parent;
      if (!p) { // 情况#0：已到树根
         if ((_x->key.size() < 1) && (0 < _N)) // 若树根已空（树还没空），则
            { _root = _x->way[0]; _root->parent = nullptr; delete _x; } // 整树降低一层
         break; // 随即收工
      } // 情况#0
      _k = p->way.find(_x); // 确定_x在p中的秩
      BTNP<T> ls  =  (0 < _k) ? p->way[_k-1] : nullptr; // 左兄弟
      if (ls && (_a < ls->way.size())) { // 情况#1L：_x有个足够“胖”的左兄弟
         _x->key.insert(0, p->key[_k-1]); // p的轴点关键码转入_x（作为最小关键码）
         p->key[_k-1] = ls->key.remove(); // ls的最大关键码转入p
         _x->way.insert(0, ls->way.remove()); // ls的最大孩子过继给_x
         if (_x->way[0]) _x->way[0]->parent = _x; // 作为_x的最小孩子
         break; // 随即收工
      } // 情况#1L
      BTNP<T> rs = (_k < p->key.size()) ? p->way[_k+1] : nullptr; // 右兄弟
      if (rs && (_a < rs->way.size())) { // 情况#1R：_x有个足够“胖”的右兄弟
         _x->key.insert(p->key[_k]); // p的轴点关键码转入_x（作为最大关键码）
         p->key[_k] = rs->key.remove(0); // rs的最小关键码转入p
         _x->way.insert(rs->way.remove(0)); // rs的最小侧孩子过继给_x
         if (_x->way[_a-1]) _x->way[_a-1]->parent = _x; // 作为_x的最大孩子
         break; // 随即收工
      } // 情况#1R
      // 情况#2：左、右兄弟均或不存在或不够“胖”，但至少存在其一
      if (ls) rs = _x; else { ls = _x; _k++; } // 以ls、rs命名之后，以下将rs归入ls
      ls->key.insert(p->key.remove(_k-1)); p->way.remove(_k); // p吐还轴点
      rs->way.traverse(LinkParent<T>(ls)); // rs的孩子们统一指向ls
      ls->way.insert(rs->way); ls->key.insert(rs->key); // 过继子树及关键码
      delete rs; // 右兄弟功成身退
      _x = p; // 上升一层，继续修复——至多可能上溯O(logn)层、合并O(logn)次
   } // while
} // solveUnderflow

    三、红黑树

    3.1 基本约束

    • 由红节点和黑节点组成；
    • 树根必须是黑色；
    • 外部节点必须是黑色；（需要在最底部放置黑色占位符变成真二叉树）
    • 红节点的孩子一定是黑色；
    • 从任意节点 x 到其每个后代 nullptr，沿途经过的黑孩子一样多。这个数目（不计 x 自身）称为 x 的黑高度。

    3.2 红黑树和 (2,4)-树

    直观理解：将红节点提升至与其（黑）父亲等高，红边折叠起来…

    每棵红黑树对应于一棵合理染色的 (2,4)-树。每一个节点合理的染色：

    • 黑；
    • 红黑；
    • 黑红；
    • 红黑红。

    因此，一棵 (2,4)-树可以对应多棵红黑树。

    3.3 红黑树是 BBST

    由于可以等嫁为 B 树，因此红黑树 h<2⋅b=O(log⁡n)h<2\cdot b=O(\log n)h<2⋅b=O(logn)。

    3.4 红黑树的插入和双红修正

    先在最底部插入节点并将其染色为红（不破坏黑高度），然后解决它和父亲都是红色的问题。此时祖父必然是黑色。

    设现在的结构：

    		|
		g [B]
	   / \
	  /   \
 [R] p     u [B/R]
	/ \     
   /   \     
  x [R] 2    
 / \    [B]   
/   \
0    1  
[B]  [B]

    u 是 uncle，需要按照黑 / 红分开讨论。

    3.4.1 RR-1

    若 u 为黑，那么将 p 旋转到上面并重新染色：

    		|
		p [B]
	   / \
	  /   \
 [R] x     g [R]
	/ \   / \
   0   1 2   u
 [B] [B] [B] [B]

    3.4.2 RR-2

    若 u 为红，那么重新染色即可：

    		|
		g [R]
	   / \
	  /   \
 [B] p     u [B]
	/ \     
   /   \     
  x [R] 2    
 / \    [B]   
/   \
0    1  
[B]  [B]

    调整不断向上蔓延，需要 O(log⁡n)O(\log n)O(logn)。

    3.4.3 代码实现

    template <typename T> 
void RedBlack<T>::solveDoubleRed() {
    for ( BNP<T> x = _x; ; ) {
        if ( !x->parent ) //若已（递归）转至树根，则将其转黑，整树黑高度也随之递增
        {  x->color = RBT_BLACK; break;  } //否则，x的父亲p必存在
        BNP<T> p = x->parent; if ( IsBlack( p ) ) break; //若p为黑，则可终止调整
        BNP<T> g = p->parent; //否则x的祖父必存在且为黑
        BNP<T> u = Uncle( x ); //以下，视x叔父的颜色分别处理
        if ( IsBlack( u ) ) { //RR-1: u为黑（含nullptr）
            g->color = RBT_RED; BNP<T> b = rotate( g ); //绕g旋转之后
            b->color = RBT_BLACK; break; //新根b与g互换颜色，即完成修复
        } else { //RR-2: u为红
            p->color = u->color = RBT_BLACK; //p、u由红转黑
            g->color = RBT_RED; g->height++; //在B-树中g是上交的关键码，故染红
            x = g; //继续上溯
        } //else
    } //for
} //solveDoubleRed

    3.5 红黑树的删除

    如果删除节点和它的孩子都是黑色，这种情况称为 双黑缺陷。假设树的结构如下：

    3.5.1 BB-1

    此时可以直接将 s 旋转上根节点并继承 p 的颜色，p 旋转到下面。

    3.5.2 BB-2R

    此时交换 s 和 p 的颜色即可。

    3.5.3 BB-2B

    此时将 s 染成红色即可。但是此时全树的黑高度减少了 1，因此需要对祖先继续递归处理（这是唯一需要递归的情况）。

    template <typename T> 
bool RedBlack<T>::remove( const T& e ) {
    if ( !BST::remove( e ) ) return false; //先按BST规则删除_p的孩子_x，接替者为_r
    if ( !RbtBalanced(_p) ) //若失衡（即原_x为黑）
        if ( IsRed(_r) ) //若接替者_r为红，则
            _r->color = RBT_BLACK; //只需令其继承_x的黑色，黑高度随即复原
        else //否则（即原_x及_r均为黑色）
            solveDoubleBlack(); //从_p出发，做双黑修正
    return true;
} //remove
